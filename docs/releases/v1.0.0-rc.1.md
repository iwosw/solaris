# Solaris 1.0 "Pauline" RC1

Release candidate 1 of Solaris 1.0, the first stable release of the Solaris
Minecraft Java Edition server (written in Rust) and the Solaris native client.
Target: Minecraft Java Edition **26.1.2**. Report problems before 1.0 final
on October 31.

## Highlights

### Settlements

- Villages are autonomous settlements: a planner builds certified buildings
  (house, workshop, storage, mine, camp) from real materials, villagers take
  building jobs, miners and lumberjacks gather resources.
- Settlements raise an army and run an economy. Players manage them through a
  server-driven dialog UI.

### Native client

- Low, Medium and High graphics presets. Medium adds HDR, bloom, atmosphere,
  shadows, god rays and water; High adds three shadow cascades, TAA and
  screen-space reflections.
- GPU-generated far terrain fed by the server's LOD channel.
- Hi-Z culling and multi-draw-indirect terrain.

### Multiplayer and plugins

- Proximity voice chat (Opus relay) and screen sharing to in-world monitors
  with owner-granted, look-gated delivery.
- Carrier-backed custom blocks for plugin Loader bundles.
- Fail-closed authentication gate with a native password API for login
  plugins.
- Opt-in in-game computer terminal block.
- Distant Horizons support.

### Gameplay

- Server-driven dialogs (show/clear, custom click actions).
- Mob capabilities as blueprint data; mob step-up; village terrain fit.
- Integrated anvil, maps, datapacks, combat, redstone, Nether, End and jigsaw
  structure generation work.

### Performance

- Section-granular checkpoints, delta chunk fan-out and a bounded WAL remove
  checkpoint stalls.
- Worldgen evaluates the density graph in 8-column fp32 batches and skips
  off-chunk ore work.
- Random ticks are sampled serially below 256 chunks; idle zombies rest their
  decision loop.

## Upgrade notes

Back up the world and configuration before upgrading. 1.0 does not open
v0.0.8 native world directories in place. Move a v0.0.8 world through Anvil
once, with each version's own binary, while the server is stopped:

```sh
# with the v0.0.8 binary
solaris --config server.toml world export-anvil --source world --destination world-anvil --receipt export.json
# with the 1.0 binary
solaris --config server.toml world import-anvil --source world-anvil --destination world-1.0 --receipt import.json
```

Then point `[data].world_dir` at `world-1.0`.

This moves the world's vanilla data (terrain, entities, players, containers).
Plugin state is **not** carried over: the imported world starts with empty
plugin storage. Keep the original v0.0.8 world directory.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/kaiserproger/solaris/v1.0.0-rc.1/install.sh | \
  SOLARIS_VERSION="v1.0.0-rc.1" bash
solaris content import --version 26.1.2 --download
```

Solaris does not redistribute Mojang data: `content import` downloads the
Mojang server once, checks its size and SHA-1 and derives a local content
cache. The server refuses to start without that cache and names the command
to run.
